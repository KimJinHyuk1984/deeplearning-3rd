# 1-2 제작 및 검증 기록

> 웹 계산표로 변경하기 전의 기록이다. 최신 구현과 검증은 [웹 계산표 검증 기록](lesson-1-2-web-table-verification.md)을 기준으로 한다.

## 실행 범위

사용자의 “했어. 다음으로 가자” 지시에 따라 1-1 확인·푸시 완료를 기록하고 1-2만 작성했다. 1-1의 본문·Python 정본은 그대로 유지했다. 홈페이지에 1-2 이동 링크를 추가했다.

## 산출물

- `index.html#lesson-1-2`: 50분 학생용 본문, 발표 조각 17개
- `assets/js/widgets.js`: 숫자 변환 연습, 관찰 데이터 산점도, 입력·정답 확인 문제
- `assets/css/lecture.css`: 위 활동의 스타일
- `files/lesson-1-2-data.py`: 관찰 문장을 입력·정답 리스트로 변환하는 코드
- 웹 내 복사 자료 2개: A1용 원본 표, E1용 두 계열 좌표 표
- `docs/lesson-1-2-guide.md`: 교사용 운영안·셀 범위·해설·공식 참고
- 목차 및 제작 상태 문서 갱신

## 수행한 검사

Node.js v22.22.2의 VM에서 실제 widgets.js의 생성 함수와 이벤트 핸들러를 실행하는 최소 DOM 하네스 및 소스 대조를 사용했다. 아래 22개 검사가 통과했다. 실제 브라우저 렌더링 검증과 구분한다.

1. 1-1 HTML 소단원과 Python 정본 보존
2. 보호 파일 4개 및 data/site.js 전체 보존
3. Python 코드 블록 2개와 다운로드 정본 문자 단위 일치(CRLF→LF 정규화, 끝 줄바꿈 보존)
4. A1 붙여넣기: 실제 탭 구분, 3열·머리글+4행
5. E1 붙여넣기: 5열·머리글+2행, G열 공백, target별 좌표 일치
6. Python 관찰 리터럴과 인코딩 사전이 엑셀 원본 표와 일치(소스 데이터 분석)
7. 소단원 2개, 발표 마커 12+17=29개, HTML ID 중복 0개
8. 로컬 자산·다운로드 및 내부 앵커 실재
9. 빈 선택값을 숫자 0으로 채점하지 않음
10. 아래/아래 인코딩 검증
11. 아래/위 인코딩 검증
12. 위/아래 인코딩 검증
13. 위/위 인코딩 검증
14. 중복 확인 시 수 유지, 답 수정 시 확인 상태 해제
15. 조합 전환 시 입력 복원 및 선택 상태 하나 유지
16. 다시 풀기에서 모든 입력·확인 기록 초기화
17. 산점도 4개 점의 x1·x2 위치, target 표식, 선택 후 원래 기록 일치
18. 확인 문제 미입력·오답 세 조합·정답 한 조합 구분, 수정 시 이전 피드백 제거
19. 신규 select 5개의 ID 고유성과 label 연결
20. 1-1 스위치 실험의 네 조합·중복 기록·초기화 회귀
21. 위젯 생성 실패 시 정적 설명 복원
22. 로컬 HTTP 자산·다운로드 9개 응답 200 및 정본 바이트 일치

추가로 `node --check assets/js/widgets.js`, `git diff --check`를 수행했다. 새 웹 런타임 의존성·외부 데이터 요청은 추가하지 않았다.
